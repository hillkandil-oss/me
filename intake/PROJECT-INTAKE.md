## Access & credentials — how to share safely

Do **not** paste passwords into chat. When the time comes:

- **WordPress:** create a dedicated admin user for me and issue an
  **Application Password** (Users → Profile → Application Passwords). Revoke it when the
  work is done.
- **WooCommerce:** Settings → Advanced → REST API → generate a Read/Write key pair.
- **Hosting/SFTP:** a scoped account, not the root/owner login.
- **Merchant Center / Search Console / GBP:** add my Google account as a delegated user
  rather than sharing your password.
- Rotate or revoke everything at project end. I'll remind you.

Also note: this container is ephemeral and is wiped when the session ends. Credentials do
not persist between sessions, so expect to re-issue them if we resume later. Never commit
them to the repository.

## What I will not invent

Per the project's truthfulness rule, if a fact is missing I will flag it, not fabricate it.
That specifically includes: business address, phone, opening hours, registration numbers,
GTINs/MPNs, product specifications, reviews, testimonials, awards, certifications, trust
badges, shipping timeframes, warranty terms, return policies, stock levels, and any
authenticity, environmental, medical, or performance claim.

If any of these arrive blank, the corresponding page ships with the gap called out to you
rather than filled with plausible-looking text. That is the single biggest driver of
Merchant Center misrepresentation rejections, so it is not a corner I'll cut.
